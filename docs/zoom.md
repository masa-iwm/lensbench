# ズーム軌跡

- `zoom`: 状態（プロジェクトの `states`、.zmx なら構成。`--states` で選ぶ）ごとに、`--var` のパラメータ（群の移動
  `G2.shift`・間隔 `7.t` など、範囲は `=下限:上限`）を減衰最小二乗で解く。評価関数は像の RMS（`--merit`、全視野・多色）と、
  `--efl`（または `--pmag`）の状態ごとの目標（`-` は目標なし）。近軸量の項の重みは像の項の 10 倍から始め、目標との差が
  `--tol`（相対、既定 1e-8）に入るまで 100 倍ずつ上げて解き直す。
- `--steps N` で隣り合う状態の間に N 点を継続法でたどる（目標は等比に、出発点は一つ前の解に両端の差の分を足した所）。
  間の点の系は前の状態の系に変数の値を入れたもの（状態が群の位置のほかにも違うと警告）。
- プロジェクトの群の移動（`shift`、状態の `set` でも）は、展開した系の `群の id.shift` の値になる（状態どうしで群の位置を比べられる）。
- 結果の `path` は点ごとに `pos`（状態 k は k、間は k + 割合）・`state`・`target`・`efl`（か `pmag`）・変数の値・`merit`（像だけの値）。
- GUI は「ズーム軌跡」のパネル（パネル → パネルを足す）で、読み込んだ系の状態（.zmx は構成）を選び、状態ごとの目標・解くパラメータを決めて「軌跡を解く」。軌跡の表と変数の図が出る（serve の `zoom`）。
- Rust は `zoom::solve`、Python は `lensbench.zoom(systems, vars, efl=[…], steps=…)`（解いた系は `"systems"`）。
